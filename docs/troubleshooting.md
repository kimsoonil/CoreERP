# 검증·문제 해결

## 검증 환경

로컬: Java 21 / Node 24 / macOS arm64. Docker 실행기가 없어 일회용 PostgreSQL 18.7의 coreerp_test DB에서 동일 JUnit을 실행했습니다. Docker/Testcontainers 자체의 성공은 GitHub Actions 결과로 구분해 확인합니다. 로컬에서 실행하지 않은 컨테이너 검사를 실행했다고 표시하지 않습니다.

| 검사                                  | 로컬 결과                       |
| ------------------------------------- | ------------------------------- |
| Java JUnit·MockMvc                    | 52개 통과                       |
| Vitest                                | 61개 통과                        |
| Playwright                            | 4개 통과                        |
| React·TypeScript 빌드 / Maven package | 통과                            |
| SQL 벤치마크                          | 독립 DB 20만 행, 원본 계획 보관 |

## GitHub 원격 검증

[2026-11-22 CI 전체 성공](https://github.com/kimsoonil/CoreERP/actions/runs/45334487149), 검증 코드 커밋 `05a2318`.

- backend: JUnit 52개를 Docker의 PostgreSQL 17 Testcontainers에서 실행.
- frontend: TypeScript·Vite 빌드와 Vitest 61개 실행.
- browser: 별도 PostgreSQL 17 demo DB에서 Playwright 4개 업무 흐름 실행.
- docker: 실제 이미지 빌드·Compose 3개 서비스 기동, 익명 API 401, Swagger UI 및 OpenAPI 인증 경로 접속 확인.
- sql-performance: 별도 PostgreSQL 17의 20만 행 벤치마크 재현, 원본 JSON 아티팩트 보관.

이 결과는 위 코드 커밋과 합성 데이터 조건에 대한 검증입니다. 운영 환경의 모든 장애나 부하 상황을 보장하지 않습니다.

## 다품목 트랜잭션 테스트

입고·출고의 두 번째 품목 이력 INSERT에 PostgreSQL 트리거로 예외를 주입합니다. 예외 뒤 첫 품목 재고, 누적 입고/예약, 문서 상태, 입출고 문서와 감사 로그가 부분 반영되지 않았는지 확인합니다. 예외 주입은 테스트 전용 DB에만 생성하고 finally에서 제거합니다.

48개 주문 요청 / 재고 5개에서 예약 성공 5개, 출고 확인 요청 24개에서 출고 문서 1개·재고 한 번 차감, 같은 요청 키 16개에서 주문 1개, 역순 다품목 요청 20개에서 교착 없이 처리되는 조건을 검사합니다. 제한된 정합성 테스트이며 최대 처리량 수치가 아닙니다.

## 발견·해결한 문제

- 기존 프로젝트에서 상품 테이블의 빈 배열 재생성과 자동 페이지 초기화가 반복 렌더링을 일으킨 경험을 반영해, CoreERP DataGrid는 서버 페이지와 이전 결과 placeholder를 명시했습니다. 검색 조건 변경 시에만 목록을 초기화합니다.
- MUI 필수 입력의 별표와 DataGrid 컬럼 메뉴 때문에 일반 label 검색이 중복될 수 있었습니다. 브라우저 검사는 role·이름·문서 행 범위를 사용해 실제 입력과 재고 열을 구분합니다.
- 현재고와 가용 재고가 둘 다 10인 화면에서는 같은 숫자가 두 번 나타납니다. 출고 취소 검사는 해당 SKU 행의 두 수량과 원본 DB 검사로 복원 상태를 확인합니다.
- 모든 화면을 정적 import하면 MUI DataGrid가 로그인 초기 번들에도 포함됐습니다. 화면 lazy import와 별도 ServerTable 모듈로 경계를 나눴습니다. MUI 공통 청크는 여전히 크며 대규모 번들 최적화 완료를 주장하지 않습니다.

## 실행 오류

- DB 연결 거부: DB_URL/사용자/비밀번호와 DB 기동 확인. 기존 회사·게임 DB 주소를 넣지 마세요.
- CSRF 403: 세션과 토큰을 함께 보내고 로그인 후 토큰 재발급. 인증이 필요한 API의 익명 401은 정상입니다.
- 테스트 초기화 거부: DB 이름이 _test로 끝나야 합니다. 운영 DB 이름을 바꾸어 우회하지 말고 새 테스트 DB를 준비하세요.
- demo 변경/암호 변경: Flyway seed는 한 번만 적용하며 기존 계정의 암호를 부팅 시 덮어쓰지 않습니다. demo를 운영으로 재활용하지 마세요.
- Testcontainers 연결 실패: 로컬 Docker 엔진을 먼저 실행하거나 별도의 일회용 PostgreSQL 환경변수로 테스트하세요. CI는 Docker 지원 Ubuntu 실행기에서 검사합니다.
- 입고/출고 409: 현재 문서 상태, 미입고 수량, 가용 재고, 재고 상한, 재사용한 요청 키의 내용이 바뀌었는지 확인하세요.
