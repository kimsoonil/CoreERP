# 일별 집계 배치 — 2차 개발

운영 배포 전인 개인 프로젝트입니다. Spring Scheduling과 MyBatis로 구현했으며 Spring Batch 라이브러리를 사용하지 않습니다.

## 기준과 데이터 흐름

Asia/Seoul 기준 2000-01-01부터 어제까지의 닫힌 날짜를 처리합니다. 확정 출고의 매출·수량·건수, 취소되지 않은 발주와 실제 입고를 각 문서 발생일로 집계합니다. 상품·고객사별 매출도 같은 스냅샷에서 계산합니다. 출고 취소는 원래 출고일의 매출을 소급 수정합니다. 회계 마감 모델은 아닙니다. 기존 실시간 보고서 API는 원본 거래 조회를 유지합니다.

원본 변경 트리거가 `daily_summary_sources`의 날짜별 버전을 올립니다. 집계 버전과 같으면 SKIPPED, 다르면 원본을 다시 읽어 날짜의 헤더·상품·고객사 집계를 원자적으로 교체합니다. 현재 원본 버전과 비교한 stale 표시로 재집계 필요 여부를 제공합니다. 빈 날짜도 명시적으로 0을 저장합니다.

## 동시 실행과 실패 복구

- PostgreSQL 트랜잭션 advisory lock으로 서버 인스턴스 간 모든 집계 작업을 직렬화합니다. 다른 작업 실행 중에는 기다리지 않고 BATCH_BUSY(409)를 반환합니다.
- 외부 잠금 트랜잭션, 별도 실행 이력 트랜잭션, REPEATABLE READ 집계 트랜잭션을 사용합니다. 최소 2개 DB 연결이 필요하며 기본 풀은 12개입니다.
- 집계 중 원본이 변경돼도 하나의 일관된 스냅샷을 저장합니다. 이후 조회에서 stale로 드러나며 다음 실행이 갱신합니다.
- 계산 실패 시 교체 전체가 롤백되고 이전 성공 결과가 보존됩니다. 별도 이력에 FAILED/CALCULATION_FAILED를 남깁니다. 원인을 고친 뒤 같은 날짜를 실행하면 됩니다.
- 집계 커밋 후 이력 완료 기록만 실패하면 BATCH_HISTORY_PENDING을 반환합니다. 데이터 반영을 실패로 단정하지 않습니다. 다음 실행은 저장된 run_id로 이전 RUNNING을 SUCCEEDED로 복구한 뒤 변경이 없으면 SKIPPED 처리합니다. 커밋되지 않은 RUNNING은 ABANDONED로 정리합니다.

## 실행

ADMIN 메뉴의 ‘일별 집계 배치’에서 날짜를 선택하고 실행합니다. 최신 여부, 실행 이력, 상품·고객사 상세 및 실패 재실행을 확인할 수 있습니다. API와 CSRF를 동일하게 적용합니다.

자동 실행은 기본 꺼짐입니다. `.env`에서 `DAILY_BATCH_ENABLED=true`로 켜면 기본 `DAILY_BATCH_CRON=0 10 2 * * *`, Asia/Seoul 02:10에 실행합니다. 어제와 최근 366일 안의 변경된 날짜 최대 50개를 오래된 순으로 처리합니다. 실패는 다음 스케줄에서 다시 대상이 됩니다. 366일 이전이나 처리량 초과분은 수동으로 처리하거나 후속 실행을 기다려야 합니다.

API: POST `/api/batches/daily`에 `{"businessDate":"2026-11-20"}`. GET 하위 `/runs`, `/summaries?from=...&to=...`, `/summaries/{date}`. 날짜 범위 최대 366일. 모든 경로 ADMIN 전용입니다.

## 마이그레이션과 검증

V1과 V900을 변경하지 않고 V901을 추가했습니다. 기존 거래를 삭제하지 않고 날짜 버전을 초기화합니다. 별도 테스트 DB에서 V900 더미데이터에 V901을 적용하고 상품·주문 수 보존, Flyway 재실행 0건을 확인합니다.

전용 통합 테스트 13개는 원본/상품/고객사 정합성, 중복 SKIPPED, 취소 후 재집계, 0건 날짜, KST 경계, 최초·교체 중 실패 롤백/재시도, 동시 실행 차단, 실행 중 원본 변경, 중단 이력 복구, 커밋 후 이력 실패 복구, 스케줄·권한·CSRF를 검증합니다. 브라우저 테스트는 실제 API와 매출 대조 및 중복 실행 보존을 검사합니다.

## 운영상 남은 점

날짜 버전 행은 동일 날짜 대량 쓰기의 경합 지점이 될 수 있습니다. 처리량 개선 수치는 측정하지 않았습니다. TRUNCATE나 트리거를 비활성화한 직접 변경은 추적하지 않습니다. 지원된 업무 API/일반 DML을 사용해야 합니다. 이력 보존·정리, 알림, 장기 누락 자동 복구 정책과 외부 운영 배포는 후속 범위입니다.
